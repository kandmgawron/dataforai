The whole setup

Six commands, then you're done

# 1. Clone and install
$ git clone https://github.com/kandmgawron/dataforai.git && cd dataforai
$ python3 -m venv .venv && source .venv/bin/activate
$ pip install -r requirements.txt

# 2. Configure AWS profile
$ aws configure --profile ridge-course-dev

# 3. Deploy infrastructure
$ make deploy-base
$ make deploy-web

# 4. Load the data
$ make seed-data

# 5. When you're done for the day
$ make destroy-all
"That's it. Six commands. Clone, install, configure your profile, deploy the two stacks, seed the data. When you're done for the day, destroy-all tears it down. On your next session, deploy-base, deploy-web, seed-data — same thing again. The seed is idempotent, ON CONFLICT DO NOTHING, so it's safe to re-run."

Where it lives

  • Aurora PostgreSQL — products, customers, reviews, policy metadata
  • DynamoDB — conversations (customer_id + conversation_id)
  • S3 — policy .txt documents, raw data files

What's intentionally messy

  • Colour data uses inconsistent naming ("red" vs "fiery_red")
  • Some fields only in descriptions, not structured data
  • Gender and materials missing from schema entirely
  • This is the problem we're solving with AI
"Forty thousand products, five thousand customers, two hundred thousand reviews, fifty thousand conversations, and forty policy documents. All pre-generated, all in the parquet files in the repo. The seed just loads them into Aurora and DynamoDB — no Bedrock calls, no cost. One thing to notice: the data is intentionally messy. Colours use different names across suppliers. Some product attributes only exist in the description text, not in structured fields. Gender exists in the source data but never made it into the database schema. This is realistic. This is what real supplier data looks like. And it's exactly the problem that embeddings and semantic search solve."
What you'll see

Ridge Assist + Ridge Insight

Ridge Assist — Customer Shop
  • Product catalogue with category filters
  • Search bar — currently SQL LIKE only
  • Product detail showing raw supplier data
  • Chat widget (questions queue for staff)
  • Colour and price filters that demonstrate where traditional search fails
Ridge Insight — Internal CRM
  • Customer lookup by name, email, or ID
  • Customer detail with conversation history
  • Conversations queue from Ridge Assist chat
  • Policy document browser
  • Product search with stock levels
Both sites start "dumb" — basic SQL queries, no AI. As we add datastores through the course, these same frontends gain vector search, embeddings, memory, and RAG capabilities.
"Once the stack is up, open Ridge Assist — that's the customer-facing shop. Browse the products, try a search. Try searching for 'red waterproof jacket under 150 pounds'. Notice it fails. Try the colour filter with 'red' — some results. Try 'fiery_red' — one result. That's the teaching point. Traditional structured search breaks when your data is inconsistent. Ridge Insight is the internal tool. Staff can look up customers, see their conversations, browse policies. Right now it's all basic SQL. No intelligence. By the end of this course, both of these will have vector search, semantic understanding, and conversational memory."
