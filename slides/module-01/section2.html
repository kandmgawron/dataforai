The full setup

Six commands

# Clone and install
$ git clone https://github.com/kandmgawron/dataforai.git && cd dataforai
$ python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt

# Deploy and load
$ make deploy-base
$ make deploy-web
$ make seed-data

# When done
$ make destroy-all
Full details in SETUP.md. Seed is idempotent — safe to re-run.

Browse policy documents DEMO FLOW — DATA DRIFT: 1. Search for "Snowdon Ghost" — finds "Snowdon Ghost Tent" by Basecamp at £299.99 (SKU: MER-DRIFT-001) 2. Click it — "Product not found". This product exists in the OpenSearch search index but NOT in Aurora. 3. Explain: "This is data drift. Meridian's search index and database have fallen out of sync. A product was added to the catalogue and indexed for search, but the database record was never created — or it was deleted and the index wasn't updated. This happens in production when you write to two systems without transactional guarantees. We'll fix this with zero-ETL integration in a later module." DEMO FLOW — DATA QUALITY ISSUES: 1. Click any product, scroll to "Raw Supplier Attributes" 2. Point out: colours stored as "forest_green" with underscores vs simple "red" 3. Note that gender and materials exist in the source but aren't in the database schema 4. "These are the kind of real-world data problems that make traditional search fail. A customer searching for 'red jacket' won't find a product tagged 'crimson' or 'fiery_red'. That's why we need semantic understanding."
